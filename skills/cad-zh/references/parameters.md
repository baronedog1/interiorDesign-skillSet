# CAD 参数

用户要求参数化或动画化 STEP，或需要设计/复核 CAD 源码参数、`.step.js` 旁车参数、CAD Viewer 控件和动画控件时读取。

## 原则

参数是模型合同的一部分。好的参数要显式表达设计意图，映射到具名几何或运动，限制在有效范围内，并让用户和模型都能预测修改后的结果。

优先保持机构/零件约束的参数逻辑，不要只追求某个相机视角看起来合理。

## 参数简报

编码前写简短内部参数简报：

- 每个参数控制什么几何或运动。
- 单位、默认值、最小/最大值、步长，以及是否无量纲。
- 参数影响哪些具名特征、基准、枢轴、轴、面或局部选择器。
- 哪些是独立输入，哪些从约束推导。
- 什么验证能证明参数正确。

装配体和机构要先识别固定枢轴、移动枢轴、连杆长度、齿轮比、轴、Joint 限位和运动分支，再创建控件。

## 命名

使用表达意图的 snake_case，与 build123d Python 源码一致：

- 推荐 `wall_thickness`、`bearing_clearance`、`hinge_angle_deg`、`lid_open`、`gear_ratio`、`link_travel`。
- 避免 `offset2`、`magic_scale`、`fix_angle`、`slider_a`，除非源码本身已有明确且一致的含义。
- 只有可能混淆时才把单位写入名称，如 `_deg`、`_sec`、`_mm`。
- 旁车参数 id 与 Python 源参数对齐；源码常量、manifest feature id、UI 标签和注释之间保持可追溯。
- `schemaVersion`、`manifest.step.path`、`durationSeconds` 等模块 schema 字段名固定；snake_case 规则适用于自定义参数和特征 id。

STEP 旁车优先在 manifest 中显式链接目标：

```js
export default {
  manifest: {
    schemaVersion: 1,
    step: {
      path: "models/path/to/model.step"
    }
  }
};
```

`manifest.step.path` 必须是工作区相对路径，禁止绝对路径、URL 和 `..`。它是面向人和工具的来源记录，不是新鲜度合同；不要添加哈希或陈旧性检查。与 STEP 同目录时，旁车命名为 `.<step-stem>.step.js`，让旧 Viewer 在缺少 `manifest.step.path` 时仍能按同名约定回退。

## 默认值与边界

默认值应生成有用、有效的模型或姿态；边界应阻止不可能、自相交或误导状态。

- 尽量使用物理有效范围：Joint 限位、正尺寸、合理壁厚、真实间隙。
- 即使 UI 已声明 `min`/`max`，代码也要 clamp。
- `step` 应匹配模型真正需要的精度，而不是只方便 UI。
- 二元状态用布尔；离散模式用 select；纯样式用颜色；只有有序量用数值。
- 有用的调试参数可以保留，但不代表真实自由度时必须标为检查控件。

## 推导，禁止漂移

从真实约束计算依赖值：

- 使用枢轴、轴、中心、边界和实测连杆长度，不要目测平移。
- 围绕正确局部基准或 Joint 组合装配变换，除非包围盒中心确实是设计基准。
- 连杆机构从固定枢轴和连杆长度求运动学；禁止在不可能的中间点间插值。
- 齿轮保持节圆、齿数和角速度比，不要凭视觉调旋转。
- 重复特征从数量、节距、半径和阵列轴推导位置。

参数修改生成器时，重新生成 STEP 并验证导出几何。旁车若只改变 Viewer 展示，必要时在标签/描述中明确它不会重建几何。

## 特征与引用

具名特征连接参数与几何：

- 明确标记源零件和装配子件。
- 旁车 `manifest.features` 使用 `#o1.2` 一类稳定局部引用；文件身份放在 `manifest.step.path`。
- 公共特征 id 用 `lid`、`hinge_pin`、`input_gear`、`lower_rocker`，不要直接暴露实例 id。
- 源码按特征角色分组常量和变换，使机构逻辑可读。
- 参数指向具体面、边、零件、枢轴或装配子件时，解析并检查选择器。

## 动画

动画参数只驱动最小真实自由度，其余量全部推导：

- 机构尽量使用一个归一化行程参数，再推导所有变换。
- 循环必须精确：终点等于起点，或通过周期函数往返。
- 不要在不兼容运动分支间混合；只有物理有效的相切、过中心或奇异位姿才能切换分支。
- 全程保持铰链中心、配合面、齿轮接触、皮带路径和滑轨轴重合。
- 样式控件与机构控件分离：颜色、显隐、高亮、剖切/爆炸、速度、播放/暂停、拖动不得改变机械事实。
- 默认保留 STEP/GLB 原始材质色。只有用户明确要求重新着色、展示风格或诊断配色时才覆盖。
- 对分支选择、符号约定、基准原点和派生比值等非显而易见逻辑写注释。

STEP 旁车用 JavaScript 实现实时 Viewer 交互和 Three.js hook；Python/build123d 是重建几何的事实源。Python 可以生成 `.step.js`，但没有真实重建链路时，Viewer 控件不能暗示会重建 STEP。

## 控件

只暴露能帮助理解模型的控件，不要暴露所有常量：

- 有范围的尺寸：滑块 + 数字输入；范围大或高精度时只用数字输入。
- 角度与归一化行程：带清晰范围和单位的滑块。
- 显隐、启用、可选细节：开关。
- 离散模式：select 或分段控件。
- 颜色：只有用户明确要求 Viewer 样式时提供；否则保留源材质。
- 动画：播放/暂停、拖动、循环、重置、速度。

描述应简短说明“改变什么”和“什么约束保持不变”。

## 验证

在代表值处验证参数：默认、最小、最大、中间行程、边界/分支位姿、用户报告失败的值。

先做确定性检查：

- `scripts/inspect refs --facts --planes --positioning`：尺度、标签、坐标系和主要基准。
- `scripts/inspect frame`、`measure`、`align`：枢轴、轴、配合面和距离。
- 可行时在源码中 assert 派生尺寸或 Joint 限位。

再按 `snapshot-review.md` 用 `scripts/snapshot` 检查视觉语义：

- 查看多个姿态；运动/动画使用 GIF。
- 涉及 Viewer 展示时比较旁车启用和禁用状态。
- 检查铰链断开、枢轴漂移、碰撞、不可能分支插值和循环跳变。
- 把视觉疑点转成测量或几何事实后才报告修复完成。

## 常见失败

- 目测关键帧破坏真实连杆长度或配合约束。
- UI 参数控制视觉变换，却命名得像几何参数。
- 两个有效姿态之间插值经过无效几何。
- 围绕包围盒中心而不是铰链、配合面或局部 frame 变换零件。
- 调试比例/偏移让零件超出真实设计包络并产生碰撞。
- `manifest.step.path` 使用绝对路径、URL、父目录逃逸或重命名后的旧路径。
- 用颜色、透明、相机或爆炸间距隐藏几何错误。
