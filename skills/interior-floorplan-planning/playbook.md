# 从原图到家具锚点

先读已有需求，按[需求访谈](playbook/requirements-interview.md)识别缺失偏好并分轮补问，形成当前项目requirements记录。确认需求与图纸事实分开；只有结构可先独立还原，不能从空白图猜家庭人数和房间用途。后续功能区、家具容量、动线与风格应能追溯到需求或明确假设。

先识图，不把 OCR 文本、旧布局或图纸朝上当空间事实。保留原图，对尺寸标注、墙厚、门弧、窗和阳台边界分别辨认。脏图可由原生绘图清理成辅助参考，但不得让补画改变原始结构。用至少一条可信尺寸定标，其他已有尺寸交叉理解；无尺寸可做注明估算的概念稿，不能宣称精准。

统一米制、Y 向上、平面 x/z；图像 y 向下在入口转换一次，不镜像截图。共享墙只建一次；每个门窗引用真实宿主墙，offset 从 a 端量到开口起边。门开向、合页与门弧不清楚就保留来源疑问，不能猜成穿墙门板。开放客餐厅用真实开放连接，不补假墙。

先划定客厅、餐厅、卧室、厨卫、阳台等功能区，再标注主体 ID。房间名称和位置以图为准，不能把餐桌区猜成客厅。全户型一次整理共用墙、地、顶；不把一个房间孤立成另一套坐标。

家具生成前先选角色、真实尺寸、正面、使用空间。床的本地 -Z 为床头，+Z 为床尾；默认床头靠墙，避开门窗与衣柜开合。沙发背向支撑墙、面向电视或会客中心；阳台边应保留通路，可按需求选单人椅，不把多座沙发硬塞进窄走道。餐桌与椅子作为一个功能组，预留拉椅、落座和绕行空间。柜门、房门、抽屉的开合域要在放置前考虑；不把床垫、桌脚、地毯等合法组合接触误判为非法穿透。

`anchor` 根据宿主墙切向及朝房间的法向，直接计算家具中心与朝向：中心=墙 a+切向×(offset+家具宽/2)+内法向×(墙厚/2+家具深/2+gap)。正面=内法向；旋转角 atan2(nx,nz)。这是生成规则，不是下游看到穿模后挪家具。此命令只处理明确指定的对象，不自动替用户重排全屋；源图指定悬空布置时不调用靠墙算法。

生成 JSON 后读取 observations，并用识图对照原图检查全屋顶视关系。问题回到原图解释、坐标、宿主、组件朝向或选型规则，再生成；观察器不自动移动、隐藏、缩小对象。技术上不可解析或引用不存在才阻止该次编译，业务争议保留草稿和说明。

要多套平面方案时，宿主原生绘图附原图和已知尺度、不可变墙门窗、每套需求差异；逐张看图后将明确选择的布局转成 JSON。不能用代码画的标注图冒充原生绘图，也不能把图片像素当施工尺寸。

## 功能先于家具，开放区域不是隔断任务

开放书房首先是桌椅与使用空间，不自动等于新房间、屏风或书架。每件大件生成前先明确：服务哪个需求、是否重复已有功能、沿哪段真实可用墙或围绕哪个中心布置、占用哪些开合与通行空间。把选型理由与取舍简短记在需求记录，不新增打分门禁。

收纳结合真实可用墙面、现有柜体或书桌整合。只有确有分隔需求且通行、视线与尺度合适，才采用自由摆放的隔断；不能因客餐厅/书房相邻就沿功能边界排柜，也不照搬风格图里的书架。选组件先看功能、容量、尺寸和正面，再看款式；尺寸冲突回选型，不拉伸产品。

规划后看全屋顶视与开放区轴测，逐件解释大件为什么在这里。解释不成立就回需求解读或选型重做，不等渲染阶段隐藏。已认可布局保持不动，新增需求另存方案版本。

组件类别还不够：先分直排/贵妃位、餐桌人数和形状等结构家族，再选目录条目；sofa.straight与sofa.cloud不是仅颜色不同的同款。平台选品若改变结构家族，保留既有位置与空间需求，回布局选型后重新编译，不能压缩异形组件充当正确家具。
