# 结构锁定的原生平面布局方法

先判断 `layoutAuthority.mode`，禁止把两类输入混在一起：

- `source-furnished`：原图已经明确给出家具和柜体，家具轮廓直接取自原图。
- `native-layout-furnished`：原图只有结构或缺少完整布置。先以原图为唯一墙、开口、
  房间边界事实，用原生绘图一次生成同画布的完整二维布局；家具、柜体和设备轮廓再从
  该 accepted 布局图提取。不得先建模后倒推布局，也不得让原生绘图改墙、改门窗或改分区。

`native-layout-furnished` 的生成提示必须列出每个空间、所需功能对象、数量、朝向、贴墙
关系和主要通道，并明确“只补家具与柜体，不修改原结构”。生成结果必须与原图尺寸完全
相同，墙双边线的回投偏差不得超过结构门禁；通过后把图片 SHA-256、提示词摘要和
`accepted=true` 写入 `layoutAuthority`。每次规划先只生成一个主候选，再做一次确定性
墙线回投；结构漂移时最多重新生成一个候选，仍失败就停止并报告输入不足，不能持续试图
或用后期描线把错误结构修回去。`source-furnished` 不创建 native layout，避免多余处理。

调用前必须同时满足 `trace-alignment.json.passed=true`、`trace-validation.json.passed=true` 和四象限视觉复核完成。参考优先级固定为：第三象限墙窗结构 > 第二象限区域与分类证据 > 第四象限完整绿紫对象组合 > 用户功能需求 > 风格参考。

提示词必须明确：

- 红色双边墙带、厚度关系、蓝窗位置、所有留白门洞和比例不变；独立规划图继续使用红墙蓝窗，禁止改成黑墙。
- 只在结构内安排活动家具和功能，不扩建、不封门、不移动窗。
- 绿紫对象按已声明的 furnishing authority 提取。已有家具原图读取原图；空户型读取
  accepted 原生布局图。两者都不得减少床垫、地垫、枕头、坐垫、柜门分格等已确认子构件。
- 输出先保证平面功能和动线，不生成透视效果图。
- 默认 `structureMode=preserve`。用户没有明确改造要求时，不新增卫浴、不移动湿区、不改变房间数量或外轮廓。

原生图完成后用模型视觉能力逐区检查墙厚、闭合、窗、门、绿紫对象和内部细节。任何结构或描线事实偏差都必须退回重做，失败候选不得作为正式交付；禁止用后期涂改掩盖错误。
