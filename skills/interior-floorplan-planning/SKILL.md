# Interior Floorplan Planning

## 输入

必需输入只有本轮源户型图。可选输入包括尺寸、房名、用户要求、产品参考和平面布局要求。

- 按 schema、项目身份、revision、artifact role 和内容摘要发现输入；目录和文件名只是推荐。
- 旧 handoff 只有在源图 SHA、项目身份和 revision 全部一致时才可复用。
- 空户型先冻结结构，再用原生绘图形成一张 accepted 平面布局；已有完整布置图直接以源图为布局权威。

## 输出

唯一正式输出是 `interior.floorplan-handoff.v3`，并绑定：

1. 源图 SHA 与原图坐标系；
2. 红色双边墙和真实墙厚；
3. `door/sliding-door/open-passage/window/fixed-glazing` 开口；
4. 阳台边界 `wall/parapet/railing/open-edge/full-height-glazing`；
5. 独立空间、空间边界和真实连接；
6. 原子家具、柜体、设备、尺寸、位置、旋转与组合关系；
7. 四象限、结构图、对象图和逐层视觉复核；
8. 平面阶段动线检查所需的结构与家具事实。

HTML、Blender、CAD 建模、机位和效果图不属于本 Skill。

## 唯一流程

1. 识别真正的源户型区域；混合长图中的产品图、说明页和效果图只能作为附件参考，不能进入结构坐标系。
2. 通过确定性图像处理定位双边墙、尺寸线、门窗符号、房名和对象轮廓；Agent 只给候选分类，不得目测另写近似坐标。每条正式向量必须由独立像素门禁重新证明贴在源图墨线上，背景色、白底和房间填色不能成为描线证据。
3. 门窗先按图形签名分类，再编译连接。窗和固定玻璃不通行；门、移门和开放通道才进入拓扑。
4. 阳台逐边分类。栏杆、矮墙和开放边不能编译成通高墙；未知边不得按住宅常识补墙。
5. 家具和设备原子化。餐桌与每把餐椅、吧台与每把吧椅分别登记；连续柜体拆为模块并用 `assemblyId` 组合。L 形/转角沙发使用 `sectional-sofa`，不得降级成普通 `sofa`；吧椅使用 `bar-stool`，不得并入吧台或柜体。曲线、圆形和异形对象直接按源图采样完整轮廓，不得先画矩形再改 `shapeClass` 标签。
6. 在一次编译中同时生成墙体、空间、尺寸、连接拓扑、对象轮廓和后端消费数据；这些不是生成后的第二轮验收，而是描线算法本身。能由代码确定的吸附、归一化、宿主墙和朝向问题在本次编译中直接处理。
7. 编译完成立即输出 `workflowStage=coauthoring-draft` 的 handoff 并进入 HTML。生产任务不再运行源像素、拓扑、对象或视觉复核强门禁，也不因它们停止。
8. 对仍有歧义但数据可计算的地方保留来源坐标和自然语言提示，交给用户在 HTML 中直接拖动、替换或删除。用户确认后形成 revision；不得让 Agent 在任务中反复修改坐标来追逐校验器。
9. 像素、拓扑、尺寸和真实案例回归只在 Skill 算法修改或发版前运行。回归失败代表代码算法有问题，必须修代码并重测，不能把失败的算法上线后让客户任务承担。

## 核心规则

- 墙、开口、阳台边界、空间和对象各有一个事实源，下游不得重新描或猜。
- 背景无墨线就不得生成实体。红墙必须有两侧源线；绿/紫对象必须有源轮廓及可见内部线。没有 accepted 绿/紫描线就禁止放组件，有描线则恰好消费一次。
- 平面 Skill 对自己输出的结构负责；建模后端不得成为第一处发现重复墙、窗超出宿主墙或门洞宿主不唯一的地方。
- 开口存在性是二值事实：源图证明存在就登记，不存在就禁止下游生成。
- 门可以在某张展示图隐藏门扇，但数据中必须保留开口位置、类型、宽度、连接空间和开启方式。
- 推拉门、固定玻璃和窗不能互相替代；玻璃材质与通行属性分开记录。
- 开放式阳台的外沿按源图分类为栏杆、矮墙或开放边，不得默认封成墙；两侧边同样逐边判断。
- 家具优先保持源图位置和朝向，不为通过动线而删线、移位或改类别。
- reviewed source model 必须在顶层写唯一 `orientationAngleUnit: "degrees"`，每个 `rotationY` 都按该单位表达。编译器只在 accepted handoff 边界转换一次为弧度；缺失、无单位或其它单位一律在源编译阶段拒绝，禁止按数值大小猜测，也禁止下游补偿。
- 普通原子家具的世界朝向必须原样传入建模。编译器把来源中等价的 `+X/-X/+Z/-Z` 表达统一为 `front=+Z`、`back/headboard=-Z` 的唯一局部轴，再计算保持同一世界朝向的 `rotationY`；不得为了统一包围盒长短轴再追加 `90°`。只有 L 形模块拆分后的独立支臂可以按支臂方向旋转。
- 家具的 `hostWallIds` 只表示轮廓实际接触且主轴平行的墙。编译器按世界坐标重算并删除脱离墙面的声明；禁止为了引导机位给自由摆放家具伪造贴墙关系。
- 每个空间必须通过真实门、移门或开放通道连接到入户可达图；其中 `enclosed` 空间至少有一个真实门或移门。这是结构完整性，不是家具净空建议。
- `shapeClass`、曲线比例和左右手性全部由编译器从源轮廓生成，输入不得手写第二份分类事实。曲线轮廓无论源数据是否重复首点闭合，都先统一为不重复首尾的开放多边形，再沿原边无形变补足到至少 12 个唯一点；禁止下游建立第二套采样事实。L/U 形保留真实凹口，四点旋转矩形仍是直线轮廓。
- 房间、家具和柜体完整轮廓必须位于楼面外边界内；相机是否能位于户型外与本规则无关。
- 用户明确要求从裁切参考完成单空间时，可见结构仍是硬事实；不可见侧按用户授权做一次有界补全并登记为假设，不再反复要求整屋图。补全不能新增参考中不存在的可见门窗。
- 只允许从原图或 accepted 原生布局取得事实；禁止从旧模型、旧渲染或下游拓扑反推。

## 生产硬停止

仅以下情况停止并一次性询问：

- 没有可读取的源户型图；
- 输入 JSON 损坏、出现 NaN/Infinity 或缺少生成几何不可或缺的坐标，导致代码无法计算；
- 需要付费、公开发布或不可逆操作。

尺寸疑点、拓扑疑点、资产缺口、文件名不同、目录不同、轻微字段拼写、扫描底色、透视、颜色、家具净空不足和原户型狭窄都不是生产硬停止；它们进入可编辑草稿。

## 建议

家具影响通行、床/沙发关系不理想、原户型过窄或尺寸不舒适均输出自然语言风险和可选调整，不修改布局、不阻止下游。

## 时间观测

图像语义判断取决于图纸复杂度；确定性编译应为秒级。每次编译必须写出 `interior.floorplan-stage-timing.v1`，分别记录输入归一化、确定性编译、预览图生成和写盘时间。发布回归时间单独统计，不计入客户建模耗时。
