# 推断、确认与停止策略

## 三类事实

- `source-backed`：来自明确尺寸、已标定正交像素或可见边界；
- `user-confirmed`：原本不可见或冲突，但用户明确确认了数值/形状；确认文本进入证据记录；
- `unresolved`：为完成首轮概念模型采用的保守默认，仍需补图或确认。

不要用置信度小数掩盖来源。每个推断写字段、取值、理由、影响组件、影响视图和解除方式。

## 可继续的推断

只影响外观且不影响配合、安全或用户明确尺寸时，可以继续生成 `provisional`，例如：

- 不可见背面的软包倒角；
- 未给出的装饰圆角；
- 概念家具的底部封板；
- 材质缝线不转为制造几何。

## 必须停止的缺失

- 采购或装配接口尺寸；
- 承载、压力、电气安全、人体安全相关厚度或间隙；
- 两张标注图对同一尺寸给出不同值；
- 单张透视图没有尺度，且用户要求真实尺寸；
- 提供视图之间无法由同一三维体解释；
- 未知侧面会改变用户要求的输出功能。

只问一个最能解除阻塞的问题；其余安全可推断项记录后继续。

## 状态升级

`provisional` 升为 `accepted` 必须重新冻结新增证据或用户确认，更新计划和哈希，重新生成 STEP，并重跑所有受影响投影、尺寸、快照和包校验。禁止只改 package 状态字符串。
