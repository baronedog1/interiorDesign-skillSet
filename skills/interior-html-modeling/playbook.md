# Playbook

1. 发现并核对 accepted handoff，不重新描线。
2. 默认编译整屋；只有用户明确说“单空间独立建模”才使用局部 scope。
3. 一次物化墙、开口、窗、阳台边界、地面和空间。
4. 先把 `area-rug/floor-rug/carpet` 规范成同一个 `rug` 类，再在规范化后的同 functionalClass 中按形态、尺寸和稳定 ID 排序。绿色/紫色只保留编辑语义，不再切断相同功能资产的匹配。
5. 将源轮廓保留为碰撞 footprint，将受管模型按允许方式缩放；用源方向和资产轴计算模型 yaw。
6. 同类资产缺失时输出 `ASSET_MATCH_GAP` 的类别、尺寸、形态和许可要求，在同一任务完成正式资产准入后重跑；不交付色块、轮廓替身或程序化方盒。
7. 导入时立即删除模板示例模型并创建当前项目 scene rig；匹配完成后必须生成当前项目自己的 coauthoring model，禁止模板示例残留。随后独立重算项目 lock 和预算摘要，生成不超过 29 MiB 的 standalone 与 native manifest，再运行浏览器验收。
8. 默认直接交付 AI 一次编译结果；如果用户发现少量错误，结构页只显示墙门窗，使用选择、调整墙、添加墙、拖动加门窗和删除墙完成修正。调整墙统一拉长与拉短；添加墙自动进入二维并允许在边界外拖画。家具只有手动进入组件页后才显示并可选，不要求从零重画。
9. 每项结构修改写入 `structure-edit-patch.v2` 并进入统一撤销栈；组件继续按原合同拖动、键盘移动、旋转、复位和删除。所有鼠标、键盘和数字输入共用唯一碰撞内核：家具按真实轮廓与高度阻止越界、穿墙和互穿；门窗保持宿主、净距并避开交叉墙；同轴墙禁止重叠，只有接近 90° 且不穿洞口的墙体相交可以通过。非法候选不落地，保持上一合法状态；非结构性影响作为建议显示。
10. 用户点击“保存新版 HTML”，浏览器把当前完整模型写回文件内 `#template-data` 并下载完整 HTML；按钮旁明确提示用户把新 HTML 发回模型。
11. 收到回传 HTML 后运行 `import_returned_html.py`，原子覆盖工作区唯一 `current.html` 和 `current-model.json`，旧文件不再参与发现。
12. 用当前模型运行非阻断动线提示，再直接进入算法机位；用户可逆编辑不要求回到平面 Skill 重审。

Skill 修改或发布前必须对最终 standalone 运行 `scripts/validate_coauthoring_collisions.mjs`，同时覆盖确定性负例和真实 CDP 指针拖动；生产客户任务不重复执行这项发版回归。
