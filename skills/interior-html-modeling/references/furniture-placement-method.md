# 家具放置算法

## 权威

中心、宽深、房间、计划 yaw 和语义轴全部来自平面 handoff。建模 Skill 不因碰撞或通道建议自行移动对象。

## 方向校准

1. 用 `rotationY + orientation.localAxes` 得到源图期望的世界 `front/back/headboard`。
2. 从中央资产标签读取模型的同角色局部轴。
3. 计算唯一模型 yaw，使模型角色轴与源图世界轴重合。
4. footprint 仍按 `planFootprintRotationY` 旋转，避免模型局部坐标差异改变平面占地。

## 关系

- 餐椅的 `front` 指向同房间最近且同 assembly/关系明确的餐桌。
- 沙发存在电视柜时，`front` 指向电视柜；没有电视柜不臆造。
- 床的 `headboard`、沙发的 `back`、柜体安装面只绑定来源证明的宿主墙。
- 关系算法输出提示，不自动改变平面布局。

## 人机共创碰撞

- AI 初次编译仍原样尊重 handoff，不因编辑器发现接触或动线风险自行搬家具。
- 用户在 HTML 草稿中移动或旋转家具时，用来源真实 footprint、竖向范围、户型边界、墙体实段与其它非地毯组件做同一碰撞判断。
- 门洞只有在洞口从地面到家具顶部完整放行时才视为可穿行；窗洞下仍有窗台墙，家具不能穿过去。
- 接触边界可以，产生正面积/正深度穿透不可以。非法候选不写入模型，画面停在最后合法位置并提示第一个阻挡对象。
- 对 handoff 中已经接受的嵌入组合（例如灶台与地柜、餐椅收进餐桌）记录编辑起点基线：可以保持、退出或不加深地移动，但不能新增碰撞或进一步靠深。

用户确认 HTML 草稿后，由平面 Skill 产生新 revision；其它后端重新编译，不维护第二套 active transform。
