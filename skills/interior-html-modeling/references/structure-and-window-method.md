# 宿主墙与窗洞方法

## 输入与语义墙编译

输入必须来自第一 Skill 当前 `floorplan-handoff.v3` 中已生成并验收的 `structure-data.json`。本 Skill 不再从第二、第三、第四象限重新编译墙。导入器按以下顺序物化：

1. 核对 handoff、唯一上游报告和结构文件哈希。
2. 核对每面墙 `adjacentRoomIds`、每个空间 `polygon/areaM2/spaceType/topologyClass` 和每条连接两端。
3. 原样复制米制墙中心、厚度、高度、窗宿主和门洞关系。
4. 用现有墙窗参数构建 Three.js 网格。

禁止重新识图、重新提取墙主轴、逐像素生成墙块或为了闭合房间补墙。结构不成立时回到第一 Skill；第二 Skill 不修复上游。

## 先墙后洞

红色墙线和蓝色窗线都位于结构带。编译时先把两者共同还原为连续灰色宿主墙，再用窗对象在宿主墙上开洞。蓝色不能直接替代整段墙，也不能只叠加透明板。

每面墙使用中心线 `start/end`、`thickness` 和 `height`。每扇窗使用 `wallId`、沿墙 `offset`、`width`、`sill` 和 `openingHeight`。

## 墙体分段渲染

对一面带窗墙，运行时按沿墙区间生成：

1. 第一个窗洞前的全高墙；
2. 窗洞范围内的窗台墙；
3. 窗洞范围内的窗上墙；
4. 透明玻璃、上下框、左右框和必要中梃；
5. 窗洞后的全高墙。

多个窗按 offset 排序处理。窗改窄或移动时，重新计算以上区间，因此多余部分自动恢复为墙。

## 合法范围

- 水平安全边距至少为 `max(0.10m, wall.thickness*0.8)`。
- `width` 不能超过宿主墙扣除两端边距后的长度。
- `offset-width/2` 和 `offset+width/2` 均在合法区间内。
- `sill >= 0`，`openingHeight > 0.30m`，顶部至少保留 `0.04m` 收口。
- 同墙窗洞之间至少保留 `0.08m` 墙带。

## 人机共创编辑联动

- 改墙长度、中心或角度时，宿主关系不变。
- 墙向内拉短后如果容不下现有门窗，不静默缩窗或挪窗；本次墙体修改停在最后合法位置，由用户先调整门窗再继续。
- 墙移动后若压到已匹配组件，则该次修改恢复到上一个合法状态。
- 墙中心线共线时只允许端点接触，任何正长度重叠都拒绝；中心线只有接近 90° 的垂直交叉可通过，斜交穿越拒绝。垂直交点若落在任一墙的门窗区间内仍拒绝。
- handoff 仍是进入编辑器时的来源事实，不被原地覆盖。HTML 允许新增、删除和修改墙门窗，但每项操作必须写入 `structure-edit-patch.v2`，标记人工来源并可撤销。
- 原始墙与人工新增墙都使用统一“调整墙”：沿墙轴拖一个端点即可拉长或拉短，宿主窗保持世界位置；8cm 内磁吸其它墙的端点或交点，已有墙是不能穿过的真实阻挡。新增墙自动进入二维俯视，使用按住拖动的两点直墙、正交吸附和人工来源标记，允许画到原户型边界外。
- 双击墙后，顶部当前对象区提供唯一墙厚输入，范围 `0.04m-0.80m`。厚度变化不改墙中心线；同一直线或平行墙的实体带不得因加厚产生面积重叠，垂直墙的结构性交叉继续允许，已有门窗和家具也不能被新厚度挤压。
- 新门窗必须吸附到唯一宿主墙，并默认占用该墙最大的连续空段；移动或改宽高后立即重新切洞。同墙门窗至少保留 0.08m 墙带，且门窗不得越出墙端、墙高或被垂直墙穿过。墙改窗仍保留宿主墙，只生成接近满宽的窗洞。
- 双击墙只锁定，不切换相机；只有墙列表“正视”按钮才进入以墙中点为焦点的正视角。对象按下在捕获阶段归编辑器，空白画布才归 Orbit；双击复用稳定点击命中，禁止因两击间抖动转动相机或改选远处墙。选择调整墙后只显示并拾取目标墙两个端点圆点，墙身不触发；端点用屏幕恒定的约 30px 可视圆点和至少 52px 透明命中代理，确保 5K 大屏与普通屏均可用人类鼠标选中。二维俯视和自由三维统一在端点高度的水平面求交，拖哪个圆点就只改变哪个端点；墙正视才使用墙面求交。双击门、移门、通道或窗同样只锁定；拖动本体只改变沿墙 offset，不改变宿主、宽高或连接空间。
- 删除墙只级联其宿主门窗，不删除无关家具；相关家具贴墙和摄像头引用转成待复核建议。
- 点击确认时输出 `human-coauthoring-revision.v1`，包含来源摘要、完整结构草稿、全部补丁和剩余建议。该 revision 要进入其它后端时，由平面 Skill 一次审阅并重新编译 accepted handoff；禁止把 HTML 草稿伪装成客户原图事实。

## 窗框表现

窗洞尺寸不变时，可从 `backend-options.json` 选择无中梃纯玻璃、固定窗、平开窗或推拉窗。
默认 `frameless-glass`，不再为每扇窗无条件添加中央竖梃。具体规则见
[backend-architectural-options.md](backend-architectural-options.md)。

## 视觉类型

- 普通窗：窗台约 0.70-1.05m。
- 高窗：窗台约 1.05-1.35m，常见于厨房或卫生间。
- 近落地窗：低窗台约 0.05-0.20m，顶部仍保留墙体收口。

类型必须来自原图窗框、尺寸、立面、房间功能或用户确认，不从“外墙开口看起来像门”直接推断。

## 结构交接

- 点击任意墙应整体选中完整语义墙段。
- 每扇窗能明确指出宿主墙。
- 门洞两侧墙端与第三象限留白一致。
- `floorBoundary` 不包含电梯井、设备井或户型外留空。
- 每面墙的 `adjacentRoomIds` 至少包含两个不同空间/室外端点；同一空间两侧的墙不得导入。
- `rooms[]`、面积和 `topology` 与上游报告完全一致；标注、空间筛选和机位语义都读取同一房间 polygon。
- 结构文件不嵌入组件目录和 placement；绿紫对象另走组件合同。
