# 白模对比度系统

## 目标

模型、地板、墙、灯具、饰品和家具仍然是纯白基础材质；即使用户关闭全部项目光，结构层次也必须可读。可读性由模板渲染系统提供，不能通过偷偷给家具上色解决。

## 固定模板配置

1. 画布背景使用中性浅灰 `#d8dcda`，不使用纯白背景。
2. 保留一盏不可由项目面板删除的中性检查方向光，只负责稳定体块明暗；它与 `scene-rig.json` 的设计光分离。
3. 检查光是唯一默认投射阴影的灯；补边光不投影，避免重复阴影和昂贵阴影贴图。
4. 墙、柜体和家具的不透明 Mesh 基础色仍为 `#ffffff`；玻璃为白色透明材质。
5. 几何边使用细、低饱和、中性灰线，仅用于识别构件分界。边线不进入材质颜色审计，也不改变白模语义。
6. 使用 `ACESFilmic`、正确的线性工作色域和 sRGB 输出。曝光只在合同范围内调整，不能用超高曝光抹掉层次。

## 运行规则

- 用户关闭“光”只关闭项目/机位设计光，不关闭检查光。
- 设计光开启时，检查光保持低强度，不能抢夺真实窗侧光方向。
- capture 路由、交互预览和 standalone 必须加载同一背景、检查光、色彩管理与曝光设置。
- 新组件必须自动获得检查边；禁止逐项目手写线框。
- `runtimeAudit.whiteModelContrastSystem` 必须同时证明：中性背景、检查主光、补边光和组件轮廓边已启用。

## 验收

- 全部项目光关闭后，墙、地面、家具和柜体仍能通过阴影、明暗面或轮廓边区分。
- 所有不透明 Mesh 的基础色仍为纯白。
- 不出现黑蒙、纯白一片、重复硬阴影、彩色检查材质或背景与白模融为一体。
- 帧像素标准差必须达到项目可读性门槛；机器通过后仍需查看真实桌面和移动端截图。

实现依据：

- Three.js 要求光照计算在线性工作色域中完成，输出通常转换为 sRGB：[Color Management](https://threejs.org/manual/en/color-management.html)。
- 环境光没有方向，过强会抹平形体；方向光和半球光可建立方向层次：[Lights](https://threejs.org/manual/en/lights.html)。
- 阴影贴图有明确性能成本，因此只允许必要主光投影：[Shadows](https://threejs.org/manual/en/shadows.html)。
