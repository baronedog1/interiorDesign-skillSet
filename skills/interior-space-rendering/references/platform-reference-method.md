# 家具资产匹配与替换

## 匹配顺序

1. 从 `layoutLock` 读取源对象类别、位置、旋转、尺寸包络、正面和锚点。
2. 在当前项目资产库优先筛选；再查平台正式资产库。筛选顺序为同品类、目标风格、尺寸可容纳、轮廓相近、可用状态。
3. 同一对象只绑定一个 canonical 资产。旧会话截图、网页缩略图和其它户型成片不能成为产品事实。
4. 不得只按“长得像”跨品类匹配，例如把边柜当电视柜、把长凳当沙发。
5. 正式资产记录 `assetSource + assetId`；品牌、SKU、尺寸和材质只使用可核验字段。

## 尺寸与锚点

- `allowedEnvelope` 来自源模型为该对象分配的真实空间，不是让资产任意放大的目标。
- 目标每一轴不得超过允许包络；还要通过墙体、家具和通道碰撞检查。
- 目标尺寸小于源尺寸时，按 `center/left-edge/right-edge/front-edge/back-edge` 或结构 ID 锚定，露出真实墙面或地面。
- 位置、旋转、类别和数量保持锁定；不能为了适配资产搬动布局。

## 通用配方

找不到可靠资产时允许 `assetSource=style-generic`，但必须：

1. `assetId=null`，不能编造品牌或 SKU。
2. `productRecipe` 写清类别、构件、轮廓、腿脚/扶手/柜门、材料和目标风格。
3. 目标尺寸和锚点仍遵守同一包络合同。
4. 结果必须像完整产品，不能只是给白方盒换颜色。

## 风格参考边界

平台和外部参考用于产品外观、材质、色彩和灯光语言。已入库资产优先通过 Q2/assetId 固化；用户在当前项目提供指定家具图片时，必须先编译 `interior.user-product-reference-manifest.v1`，标记图片内产品区域并逐槽位绑定，之后才能作为 `user-product-reference` 进入请求。源截图继续拥有结构、空间、布局和机位；产品参考图只拥有已绑定槽位的产品身份与外观，图中的墙窗、吊顶、家具位置或房间比例不得复制到当前项目。被拒绝、未完成或无 accepted review/receipt 哈希链的渲染候选不得作为任何后续参考。
