# 执行方法

## 1. 从像素得到组件区域

先冻结视图，再用粗前景/背景种子建立产品区域；随后用每个组件种子在产品区域内部做梯度约束的
分水岭。Agent 只解释“这块是坐垫/扶手/靠背”，代码负责最后的像素归属。输出源图、产品掩膜、
彩色组件叠图和无底图分区图，逐张视觉复核。

## 2. 主视图直接拉伸

优先选择能看清组件分块的俯视图。每块顶视区域沿竖直方向拉伸，得到与顶视掩膜天然一致的初始
体；主视图不是优化目标，而是不可更改的生成输入。

## 3. 其它视图逐向切除

正视图把不在 `x-z` 组件区域内的体素切掉；侧视图再把不在 `y-z` 区域内的体素切掉。更多已注册
正交视图继续求交。不得先平滑、拟合类别体块或移动组件来规避切除。

## 4. 拼装与遮挡

各组件共用整数世界网格。按可见层级合成投影，并检查组件接触、支撑、允许软缝和明确遮挡。
底座等被遮挡部分可补足，但补足体不得改变已提供视图的最前可见掩膜。

## 5. 自动验收

从最终占用体生成每个视图的组件标签图和整件掩膜，与 evidence 逐像素 XOR。任何一个提供视图或
组件非零即返回区域分割/注册/雕刻阶段；不再用边界距离阈值吞掉形状错误。

## 6. 双外观交付

结构通过后，从同一个 `visual-hull-state.v1` 生成单产品 HTML。白模是默认检查状态，源色读取
`components[].material`；切换前后网格、尺寸、组件层级与相机不变。组件包把 state 哈希写入
`appearance.geometryStateSha256`，不打包第二份彩色模型。

## 7. 唯一接受决定

桌面与手机必须运行同一个 standalone，生成绑定 state/HTML 哈希的 `product-browser-qa.v1`。组件包脚本
一次性核对 plan、逐视图 evidence、源图、state、零异或报告、standalone 和 browser QA：无推断的
candidate 才派生为 accepted；含任何 `single-view-inferred` 的 state 只能派生为 provisional。state 不回写、
不复制，也不另外维护“验收后模型”。
