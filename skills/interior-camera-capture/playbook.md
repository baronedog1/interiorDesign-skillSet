# 从真实空间求机位

先确认 HTML、scene 和布局摘要同版；用户编辑后先重新导入编译。保留用户已经指定的机位参数，不拿自动搜索覆盖认可构图。各空间按正视主图在前、斜视补充在后排序。客厅分别以沙发与电视为主体生成两个有符号正面机位；不能只把所有家具的平均中心当成正视目标。

## 全屋与通用求解

全屋 overview 按楼面包络生成鸟瞰；plan 使用正交投影，up=[0,0,-1]，不镜像字。全屋图暂去顶面是明确展示状态，不是删除结构。

每个房间先取 room.subjectIds 中的本房对象；缺主体时按房名与组件类别取本房家具，不从邻房借主体。采样房内 7×7 平面点、1.40/1.25/1.55m 三种相机高度，候选先避开墙厚、开启门扇、窗帘和家具包络，距主体至少 .45m，完整房间俯仰限 ±12°。投影包络求所需 FOV，输出上限90°。这些是当前实现参数，不是用户方案的硬性美学门槛。

排序公式：max(0,所需FOV−90)×50 + (1−主体可见抽样比例)×160 + 前景遮挡比例×140 + 所需FOV + |相机高−1.4|×3；正视另加横向偏移绝对值×5。抽样是近似包络射线，不是真实像素级无遮挡证明。主体完整投影不满足、可见比<.55 或近景占幅>.35 时标 review，仍截图。

正视先取 frontWallId，缺省按主体正面找法向平行的真实相邻墙。沿朝室内法向35档距离、0/±.18m横移、三档高度求站位；无解返回带原因候选，不为改善机位而隐藏墙和家具。只有用户明确要求白模／空白槽位渲染时，才按原生绘图的模式规则暂隐家具和柜体，建筑与布局 JSON 不变。完整室内图不好时仍保留该全室图及问题；不自动用局部特写替代整室图。若需特写，另行明示其用途。

## 卧室算法

主体优先用户声明的床与床头柜；先识别床头 -Z 对应的真实墙，正视沿床尾方向朝床头看。斜角要同时读清床、床头墙、门和衣柜关系；不从墙后穿过床头拍。检查图片床头是否靠墙、床侧是否被门板遮挡；错了分别回规划锚点或相机源规则。

## 客厅算法

主体优先沙发、茶几与电视组；拍会客关系与电视方向的互补机位。正视以明确 frontWallId 或主体朝向为准。前景茶几/电视过大时修改候选目标/站位，不缩小家具。阳台边单椅与通路都要看见，不能把隔壁餐桌当客厅主体。

## 餐厅算法

主体为完整餐桌椅组，先按最外侧椅背包络求画幅，再考虑吊灯和背景柜。正视沿餐厅参考墙法向，不拿桌中心近景替代全组。逐图看椅子是否被裁、拉椅区是否被柜体夹住；摆放问题回规划，相机问题回候选生成。

## 厨房、卫生间

厨房以操作台/柜体和通道为主体，卫生间以台盆、马桶、淋浴区为主体；只取本房组件。小空间仍先求实际房内站位，不从墙后拍。无完整自然视角时明确交付局部或额外约定的剖切展示，不以隐藏实体冒充室内摄影；当前自动搜索不自动制作剖切。

## 书房、阳台及其他空间

书房取书桌/座椅及收纳，阳台保留栏杆与出入口；名称模糊则沿原图确认，不换成另一种房间。有洗衣机/台盆/坐凳时，分别沿设备的真实正面轴生成正视主图，相距两端的设备不强塞同一主体包络；长轴纵深图只是补充，不能把侧面标成设备正面。只有空房建筑主体才允许选房间长轴两个方向。不伪造摆件。

最后用真实浏览器逐张截图，并由 Agent 看主体完整性、床/沙发正反、门窗遮挡、近景占幅与房间归属。问题说明保存到 visual-review.json；修源规则重拍，不把 `ready` 当视觉通过。截图只关本任务打开的浏览器。
