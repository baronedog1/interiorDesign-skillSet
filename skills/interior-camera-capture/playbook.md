# 执行手册

## 零、冻结本轮拍摄范围

默认按全部空间执行。若用户明确指定“只拍客厅、餐厅”等范围，在 `camera-plan.v8` 写入 `captureScope`，把主空间、允许进入画面的源拓扑相邻上下文、其余排除空间完整分区并记录原因。该分区必须与原生模型 `model-scope.v1` 一致。不要为了满足旧的全屋数量假设补拍无关房间，也不要把未拍房间从结构数据中删除。

## 一、预检

1. 同时读取动线 result、结构 v3、原生模型清单和模型文件。
2. 运行 `validate_circulation_gate.py`，确认动线已接受且绑定当前原生模型 SHA-256。
3. 核对 `floorplanId`、handoff digest、原生模型 SHA-256、后端类型和 capture adapter。
4. 核对原生模型具备 raycast、depth、entity ID、visibility 和 native camera render；连接开口必须同时通过四角前向投影和归一化 Entity-ID 墙体遮挡率审计。
5. 不以 GLB 代理 Blender，不以网页代理 CAD，不以截图代理任何原生模型。

## 二、逐空间计算

1. 根据房间类型选功能主角，而不是先找空墙。
2. 运行 `solve_frontal_camera_seeds.py`，对拍摄范围内每个空间按功能优先级、已接受贴墙关系、真实墙距离、墙长和 ID 求唯一正视种子。算法输出直接进入下一步，不请求用户确认。
3. 原生适配器一次量取全部空间的 `anchorEnvelope/referenceFacade/contextEnvelope` 完整 OBB 八角点和真实可退距，写入一个 measurement 文件。
4. 运行 `compile_camera_candidates.py` 一次编译全部空间；以 seed 指定的真实背景墙和法向为唯一主图轴，不由 Agent 另选角度或逐空间手工拼命令。
5. 批量编译器用统一公式计算画幅、5% 安全后退距离和焦段链；将候选相机写入明确的 `cameraHostRoomId`，并绑定冻结房间多边形射线交点得到的真实可退距。
6. 对固定顺序中的第一张可拟合候选执行合法站位、开口连通和原生 raycast 检查。
7. 先保存一张同一后端原生主预览并执行机器投影门禁；通过即停止。失败时记录 `failureCodes`，最多再保存下一张回退预览。

## 三、候选评分

固定检查：

| 项目 | 门限/优先级 |
|---|---|
| 背景墙法向偏差 | `≤1°` |
| 俯仰 | `≤0.25°` |
| 横滚 | `≤0.1°` |
| 对齐残差 | `≤0.25°` |
| 四边边距 | 每边 `≥6%` |
| 左右边距差 | `≤3%` |
| 近远尺度比 | `≤1.18` |
| 前景遮挡 | `≤8%` |
| `mustShowElements` | 全部完整 |
| 空间识别 | 第一眼可识别功能主角 |

候选按 seed 和固定顺序逐张执行硬门限，选第一张合格者，不再用主观总分覆盖顺序或硬门限。每个拍摄空间必须有一张 `one-point-frontal` 主图。主候选通过后禁止继续截图；只有机器门禁失败才能进入下一张回退候选。

## 四、后退和遮挡

1. 当前房间内后退，相机点仍须落在该房间多边形内。
2. 经真实开口进入连通空间后退，同时切换 `cameraHostRoomId` 并重新计算可退距。
3. 沿背景墙平移相机。
4. 将次要上下文拆为关系图。
5. 逐级使用 `35/32/28/24/22/20mm`。
6. 只有原生射线证明局部实体挡住主角时才隐藏该实体。
7. 不能整体隐藏相邻房间；过道尽端房间必须保留。

## 五、原生截图

1. 运行 `validate_camera_manifest.py`，从源墙和相机向量重算几何。
2. 运行 `capture_model_views.py --structure structure-data.json`，由正式调度器复验机位与 model scope，记录设备压力并占用最多两个全局截图槽位之一，再按 `modelBackend` 调用唯一原生适配器。禁止直接执行适配器；同一作业中的 shots 顺序拍摄并复用一个原生进程。
3. 每个 shot 必须同时生成纯水泥空结构 Q1、家具 QA 图 Q2、二维机位证据、相机状态 JSON、Entity ID、Room ID、Depth 和 semantic frame；候选审计必须用路径与哈希绑定该相机状态 JSON。
4. semantic frame 写入后端和原生模型哈希；缺任一项不能编译 scene map。
5. 可见性编译后把完整 included/excluded 决策写入独立 QA audit；对外 scene map 只留 included 集合，并把结构归属裁切到当前可见房间。不得为了“解释排除原因”把画外房间或开口名称带入生成输入。
6. `build_shot_scene_map.py` 打包当前 camera plan，并以同帧原生 semantic frame 复算每个 anchor 的四边边距；缺失、裁切或任一边 `<6%` 立即失败。
7. `build_shot_scene_map.py` 只做单向转换，不补写识图结果；验证器必须独立重跑正视 seed 算法，并回读 plan、相机状态和 semantic frame 复算上述结果。

## 六、Agent 视觉复核

只进行一次并排终审：查看算法实际生成的一张主候选（或主候选失败证据与一张回退候选）、Q1/Q2 双状态证据、二维机位图和语义遮罩。终审只负责接受或归因明确错误，不重新选机位、不追加试拍：

- 背景墙的竖线竖直、水平分界水平。
- 主角没有裁切，四周留白真实存在。
- 近处和远处尺度没有明显夸张。
- 开放通道后的空间保留，局部遮挡物的移除没有破坏结构理解。
- Q1 只隐藏组件，不删除组件 JSON，也不绘制槽位轮廓、色块或编号。
- 家具参考图与槽位图来自同一相机、模型和像素尺寸，墙体与地面都保持同一水泥外观。
- 房间、开口、组件 ID、图片区域和世界坐标与原生证据一致。

## 七、四象限交接

- 左上（Q1）：纯水泥毛坯结构图；活动家具和柜体隐藏，不显示槽位覆盖，完整槽位只保留在 JSON。
- 右上（Q2）：同一水泥墙地面、同一模型、同一相机的活动家具和柜体 QA 图；默认生成请求不提交此图。
- 左下：原生相机二维证据。
- 右下：渲染 Skill 回填的图像生成最终图；机位阶段保留占位，原生场景截图不得冒充 Q4。
- 底部：从 camera plan v8 和 shot-scene-map v9 确定性读取 JSON 解读。

## 失败分类

- `structure-source-error`：墙、开口、房间连接错误，退回平面 Skill。
- `native-model-error`：实体、模型尺寸、组件或碰撞错误，退回当前建模后端。
- `circulation-gate-error`：动线未通过或模型哈希变化，退回 `interior-circulation-planning`。
- `reference-wall-error`：背景墙选错或不连续，重新选墙。
- `camera-geometry-error`：法向、光轴、射线、退距或焦段错误，重算候选。
- `framing-error`：主角裁切、边距、尺度或前景遮挡失败，按后退链处理。
- `native-adapter-error`：计划正确但原生相机状态不一致，修当前后端适配器。
- `semantic-projection-error`：ID/Depth/房间投影错误，修原生投影链。
- `render-preservation-error`：机位正确但最终效果图漂移，退回渲染 Skill。

失败时修产生错误的唯一事实，不修改下游 JSON 去迎合错误画面。

算法可以证明的 seed 重算、合法后退、沿墙平移和一次有界回退直接执行，不逐次向用户确认。只有输入证据缺失或冲突、用户设计取舍、不可逆/付费/公开操作才合并成一次问题。
