# Playbook

## 客户任务

1. 先用 `--backend html` 读取项目唯一当前 HTML 和同 revision 结构；生成 camera scene receipt 并调用唯一求解器。
2. HTML 原生事实完成二次收敛后冻结正式 plan。Blender/CAD 只能接收这个 plan；没有 plan 时停止并回到 HTML 求解，不读取后端场景重新选角度。
3. 用 `unified_camera_solver.py` 一次求出全部请求空间。单图使用 `--views-per-room 1`；用户明确要求多图时才提高数量。用户已明确确认红箭头或机位方向时，由生产入口附带可追溯的 `interior.user-camera-intent.v1`；求解器只保留与其有向光轴一致的严格墙法线候选，禁止再用主体默认轴覆盖用户方向。
4. 方向主体先锁定正面轴与真实背景墙。卫浴和阳台设备从最近房间边界求出背墙与有符号正面；候选必须优先从正面侧拍摄。多主体空间同时计算逐主体投影重叠率和中心间距，重叠严重的墙族不能压过无重叠严格正视解。房内候选还必须给主体最近表面保留至少 `1.10m`。
5. 房内和后退解都从 VTK Entity-ID 结果计算目标房间墙、开口和主体的屏幕包络，形成唯一 `projectionCrop`：顶部保持 `0`，左右与底部按墙体证据裁切。房内解保持零隐藏；后退解的裁切框内剩余真实遮挡由同一求解器有限隐藏。
6. HTML 先按 provisional plan 生成原生 facts，再由同一个求解器完成最终选择。最终 plan 冻结后，任何后端都不能再次调用求解器。
7. 使用同一计划和模板声明的原生截图器输出正式 PNG。Blender 使用经过投影矩阵证明的垂直 FOV/windowCenter 映射；材质、灯光和采样由 Blender 后端模板负责，Camera 不得用低质量检查图覆盖正式渲染。
8. 每张 PNG 与同名 facts JSON 立即落盘。评估可以提示构图、畸变或内容问题，但不得阻断已有截图交付。
9. 需要效果图时，直接把正式 `camera-image-facts.v3` 与同名 PNG 交给渲染 Skill；不再编译 scene map 或旧 camera-plan 合同。

## 画面判断

主体正面轴、背景墙支持关系、居中、主体表面净距、完整度、自然透视、上下空间、遮挡和目标空间清晰度统一作为排序目标。房内存在舒适净距的严格正视解时优先；房内只能贴着床尾、衣柜或柜体站位时，允许后退和剖开真实交点墙。没有候选达到全部理想值时仍选择当前排序最高的严格正视镜头并截图，问题写入 `qualityAdvisories`，不阻断交付。

## 失败恢复

- 输入准备失败：修输入适配或源模型，不手写语义清单。
- 场景生成失败：修当前 HTML 网格或唯一场景生成器；禁止创建代理场景继续。
- 所有严格正视候选都有质量提示：仍选择排序最高者并截图，后续修通用算法；只有墙体或结构事实缺失、连几何候选都无法形成时才停止。
- 后端不支持完整 FOV/windowCenter/projectionCrop：升级该后端截图适配器，不修改公共计划、不新增备用求解器。
- VTK/EGL 警告但输出齐全：作为运行证据记录；没有 RGB/ID/Depth 时才算失败。
- 单张画面不理想：仍交付，并把问题加入算法研发回归；客户任务禁止手改该图坐标。

## 发版

发版前运行包内合同测试、当前十空间 fixture、至少三个异构冻结输入、HTML 回归、Blender 原生建模/场景导出/截图与旧入口负向扫描。CAD 模板必须通过静态合同验证；CAD 原生 Skill 改动时再做独立原生回归。
